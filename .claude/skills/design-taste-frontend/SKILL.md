# tasteskill: 反套路前端技能

> 落地页、作品集和重构项目。不包括仪表盘、数据表格或多步产品 UI。
> 以下每一条规则都是**情境化**的。没有任何一条会自动触发。先阅读需求简报，再只选取适用的部分。

---

## 0. 需求推断（在做任何事情之前先理解上下文）

在触碰代码或调整参数之前，**推断用户真正想要什么**。大多数 LLM 设计产出效果不好，是因为模型跳到了默认审美，而没有先理解上下文。

### 0.A 先阅读以下信号
1. **页面类型** - 落地页（SaaS / 消费级 / 代理机构 / 活动）、作品集（开发者 / 设计师 / 创意工作室）、重构（保留 vs 全面改造）、编辑 / 博客。
2. **用户使用的**氛围词** - "极简"、"平静"、"Linear 风格"、"Awwwards"、"粗野主义"、"高端消费级"、"Apple 感"、"活泼"、"严肃 B2B"、"编辑感"、"代理机构感"、"玻璃态"、"暗黑科技"。
3. **参考信号** - 用户分享的 URL、粘贴的截图、提及的产品、竞品品牌。
4. **受众** - B2B 采购团队 vs 注重设计的消费者 vs 浏览作品集的招聘人员。受众决定审美，不是你的品味。
5. **已存在的品牌资产** - logo、配色、字体、摄影。对于重构项目，这些是起始材料，不是可选输入（见第 11 节）。
6. **隐性约束** - 无障碍优先的受众、公共部门、受监管行业、信任优先的电商、儿童产品。这些约束**覆盖**审美偏好。

### 0.B 在生成前先输出一行"设计解读"
在任何代码之前，用一行说明：**"解读为：\<页面类型> 面向 \<受众>，采用 \<氛围> 语言，偏向 \<设计系统或审美家族>。"**

示例解读：
- *"解读为：面向技术决策者的 B2B SaaS 落地页，采用 Linear 风格极简语言，偏向 Tailwind 工具类 + Geist + 克制动效。"*
- *"解读为：面向招聘经理的独立设计师作品集，采用编辑 / 动态字体排版语言，偏向原生 CSS + 滚动驱动动画 + 自定义字体。"*
- *"解读为：公共部门服务网站重构，采用信任优先语言，偏向 GOV.UK Frontend 或 USWDS。"*

### 0.C 如果需求简报模糊，只问一个问题，不要猜测
只问**一个**澄清问题 - 绝不要抛出多个问题 - 且只在设计解读确实存在分歧时。示例：*"这个设计应该更接近 Linear 的简洁，还是 Awwwards 的实验感？"*

如果你能从上下文中自信推断，**不要问**。直接声明设计解读并继续。

### 0.D 反默认原则
不要默认使用：AI 紫色渐变、深色网格上的居中 Hero、三个相同的特性卡片、到处滥用通用毛玻璃、无处不在的无限循环微动画、Inter + slate-900。这些是 LLM 的默认值。基于设计解读刻意突破它们。

## 1. 三个旋钮（核心配置）

在设计解读之后，设置三个旋钮。以下所有布局、动效和密度决策都受这三个旋钮控制。

* **`DESIGN_VARIANCE: 8`** - 1 = 完美对称，10 = 艺术化混乱
* **`MOTION_INTENSITY: 6`** - 1 = 静态，10 = 电影级 / 物理效果
* **** - 1 = 画廊级 / 通透，10 = 仪表盘级 / 密集数据

**基准值：** `8 / 6 / 4`。除非设计解读覆盖，否则使用这些值。不要要求用户编辑此文件 - 覆盖通过对话进行。

### 1.A 旋钮推断（设计解读 → 旋钮值）
| 信号 | 变化度 | 动效 | 密度 |
|---|---|---|---|
| "极简 / 干净 / 平静 / 编辑感 / Linear 风格" | 5-6 | 3-4 | 2-3 |
| "高端消费级 / Apple 感 / 奢侈 / 品牌" | 7-8 | 5-7 | 3-4 |
| "活泼 / 狂野 / Dribbble / Awwwards / 实验性 / 代理机构" | 9-10 | 8-10 | 3-4 |
| "落地页 / 作品集 / 营销网站（默认）" | 7-9 | 6-8 | 3-5 |
| "信任优先 / 公共部门 / 受监管 / 无障碍关键" | 3-4 | 2-3 | 4-5 |
| "重构 - 保留" | 匹配现有 | +1 | 匹配现有 |
| "重构 - 全面改造" | +2 | +2 | 匹配现有 |

### 1.B 用例预设
| 用例 | 变化度 | 动效 | 密度 |
|---|---|---|---|
| 落地页（SaaS，主流） | 7 | 6 | 4 |
| 落地页（代理机构 / 创意） | 9 | 8 | 3 |
| 落地页（高端消费级） | 7 | 6 | 3 |
| 作品集（设计师 / 工作室） | 8 | 7 | 3 |
| 作品集（开发者） | 6 | 5 | 4 |
| 编辑 / 博客 | 6 | 4 | 3 |
| 公共部门服务 | 3 | 2 | 5 |
| 重构 - 保留 | 匹配 | 匹配+1 | 匹配 |
| 重构 - 全面改造 | +2 | +2 | 匹配 |

### 1.C 旋钮如何驱动输出
将这些（或用户覆盖的值）用作全局变量。本文档中所有交叉引用都指向这些确切的变量名 - 绝不要发明别名，如 `LAYOUT_VARIANCE` 或 `ANIM_LEVEL`。

## 2. 需求简报 → 设计系统映射

一旦有了设计解读（第 0 节）和旋钮（第 1 节），就选择合适的基础方案。不要为已有官方包的东西自己写 CSS。不要把审美趋势伪装成官方系统。

### 2.A 何时使用真正的设计系统（使用官方包）
| 解读为… | 选用 | 原因 |
|---|---|---|
| Microsoft / 企业 SaaS / 仪表盘 | `@fluentui/react-components` 或 `@fluentui/web-components` | 官方 Fluent UI，Microsoft token，无障碍已搞定 |
| Google 风格 UI，Material 风味产品 | `@material/web` + Material 3 token | 官方，可通过 Material Theming 配置主题 |
| IBM 风格 B2B / 企业分析 | `@carbon/react` + `@carbon/styles` | 官方 Carbon，成熟的密度数据处理模式 |
| Shopify 应用界面 | `polaris.js` web 组件 / Polaris React | Shopify 后台 UI 强制要求 |
| Atlassian / Jira 风格产品 | `@atlaskit/*` + `@atlaskit/tokens` | 官方 Atlassian 设计系统 |
| GitHub 风格开发工具 / 社区页面 | `@primer/css` 或 `@primer/react-brand` | 官方 Primer；Brand 变体用于营销 |
| 英国公共部门服务 | `govuk-frontend` | 法律 / 监管要求 |
| 美国公共部门 / 信任优先 | `uswds` | 同上 |
| 本地商户 / 代理机构 MVP | Bootstrap 5.3 | 保守、快速、能用 |
| 现代无障碍 React 基础 | `@radix-ui/themes` | 基础组件 + 精致主题 |
| 自己掌控组件的现代 SaaS | shadcn/ui（`npx shadcn@latest add ...`） | 代码归你所有，易于定制；绝不要以默认状态交付 |
| 基于 Tailwind 的现代 SaaS / AI 营销 | Tailwind v4 工具类 + `dark:` 变体 | 独立开发和小团队的默认选择 |

**诚实规则：** 如果需求简报解读为以上某个系统，安装并使用**官方**包。不要手工重新创建它的 CSS。不要导入系统的 token 然后覆盖 90%。

**每个项目一个系统。** 不要在同一个项目中混用 Fluent React 和 Carbon。不要在一个 Material 3 应用中导入 shadcn/ui 组件。

### 2.B 当需求是一种审美而非系统时
对于这些方向，**没有单一的官方包**。使用原生 CSS + Tailwind + 维护良好的组件库构建。在代码注释中诚实地标注哪些是借鉴灵感、哪些是官方素材。

| 审美风格 | 诚实的实现方式 |
|---|---|
| 毛玻璃 / "磨砂玻璃" | `backdrop-filter`、分层边框、高光叠加层。为 `prefers-reduced-transparency` 提供纯色填充回退。 |
| Bento（Apple 风格磁贴网格） | CSS Grid 混合不同尺寸的单元格。没有单一库拥有这个。 |
| 粗野主义 | 原生 CSS、等宽字体、原始边框。没有库。 |
| 编辑 / 杂志风格 | 衬线字体、非对称网格、 generous 留白。没有库。 |
| 暗黑科技 / 黑客风格 | 等宽字体 + 霓虹强调色、终端元素。没有库。 |
| 极光 / 网格渐变 | SVG 或分层径向渐变。没有库。 |
| 动态字体排版 | 原生 CSS 动画、滚动驱动动画、GSAP 用于劫持。没有库。 |
| **Apple Liquid Glass** | Apple 仅在 Apple 平台上文档化。**没有官方的 `liquid-glass.css`。** Web 实现是使用 `backdrop-filter` + 分层边框 + 高光的近似方案。在注释中明确标注为近似方案。 |

## 3. 默认架构与约定

除非设计解读选择了真正的设计系统（第 2.A 节），否则以下是默认方案：

### 3.A 技术栈
* **框架：** React 或 Next.js。默认使用 Server Components（RSC）。
  * **RSC 安全：** 全局状态只能在 Client Component 中工作。在 Next.js 中，将 provider 包裹在 `"use client"` 组件中。
  * **交互隔离：** 使用 Motion、滚动监听器或指针物理效果的任何组件必须是独立的叶子组件，顶部带有 `'use client'`。Server Component 仅渲染静态布局。
* **样式：** **Tailwind v4**（默认）。仅在现有项目要求时使用 Tailwind v3。
  * v4：不要在 `postcss.config.js` 中使用 `tailwindcss` 插件。使用 `@tailwindcss/postcss` 或 Vite 插件。
* **动画：** **Motion**（原 Framer Motion）。从 `motion/react` 导入（`import { motion } from "motion/react"`）。`framer-motion` 包仍然作为遗留别名工作 - 新代码中优先使用 `motion/react`。
* **字体：** 始终使用 `next/font`（Next.js）或使用 `@font-face` + `font-display: swap` 自托管。生产环境绝不要通过 `<link>` 链接 Google Fonts。

### 3.B 状态管理
* 独立 UI 使用本地 `useState` / `useReducer`。
* 全局状态**仅**用于避免深层 prop 钻取 - Zustand、Jotai 或 React context。
* **绝不**使用 `useState` 追踪由用户输入驱动的连续值（鼠标位置、滚动进度、指针物理、磁性悬停）。使用 Motion 的 `useMotionValue` / `useTransform` / `useScroll`。`useState` 在每次变化时重新渲染 React 树，并在移动端崩溃。

### 3.C 图标
* **允许使用的库（优先级顺序）：** `@phosphor-icons/react`、`hugeicons-react`、`@radix-ui/react-icons`、`@tabler/icons-react`。
* **不推荐：** `lucide-react`。仅在用户明确要求或项目已依赖它时才可接受。
* **绝不手写 SVG 图标。** 如果缺少某个字形，安装第二个库或从基础元素组合 - 不要从头绘制图标路径。
* **每个项目一个系列。** 不要在同一个组件树中混合使用 Phosphor 和 Lucide。
* **全局标准化 `strokeWidth`**（例如 `1.5` 或 `2.0`）。

### 3.D Emoji 策略
默认不鼓励在代码、标记和可见文本中使用。用图标库字形替代符号。**覆盖：** 仅当用户明确要求活泼 / 聊天风格 / 社交原生氛围时才允许使用 emoji - 即使如此也要谨慎有目的地使用。

### 3.E 响应式与布局机制
* 标准化断点（`sm 640`、`md 768`、`lg 1024`、`xl 1280`、`2xl 1536`）。
* 使用 `max-w-[1400px] mx-auto` 或 `max-w-7xl` 包裹页面布局。
* **视口稳定性：** 全高 Hero 区域**绝不**使用 `h-screen`。始终使用 `min-h-[100dvh]` 防止移动端布局跳动（iOS Safari 地址栏）。
* **Grid 优于 Flex 数学计算：** 绝不使用复杂的 flexbox 百分比数学（`w-[calc(33%-1rem)]`）。始终使用 CSS Grid（`grid grid-cols-1 md:grid-cols-3 gap-6`）。

### 3.F 依赖验证（强制）
在导入任何第三方库之前，检查 `package.json`。如果包缺失，先输出安装命令。**绝不**假设库存在。

## 4. 设计工程指令（偏差纠正）

LLM 默认使用陈词滥调。主动覆盖这些默认值。每条规则都有情境感知的覆盖路径。

### 4.1 字体排版
* **展示 / 标题：** 默认 `text-4xl md:text-6xl tracking-tighter leading-none`。
* **正文 / 段落：** 默认 `text-base text-gray-600 leading-relaxed max-w-[65ch]`。
* **无衬线字体选择：**
  * **不推荐作为默认：** `Inter`。优先选择 `Geist`、`Outfit`、`Cabinet Grotesk`、`Satoshi`，或适合品牌的衬线字体。
  * **覆盖：** 当用户明确要求中性 / 标准 / Linear 风格感觉，或需求是公共部门 / 无障碍优先网站时，Inter 是可接受的。
* **已知搭配：** `Geist` + `Geist Mono`、`Satoshi` + `JetBrains Mono`、`Cabinet Grotesk` + `Inter Tight`、`GT America` + `IBM Plex Mono`。

* **衬线纪律（非常不推荐作为默认）：**
  * 衬线作为任何项目的默认字体**非常不被推荐。**"感觉有创意 / 高端 / 编辑感"不是选择衬线的理由。代理机构默认心理模型"创意简报 = 衬线"是生产测试中被测试最多的 AI 特征。
  * **仅当以下情况之一明确成立时，衬线才是可接受的：**
    - 品牌简报明确命名了衬线字体，或
    - 审美家族确实是真正的编辑 / 奢侈 / 出版 / 手稿 / 传统 / 复古风格，且你能说明为什么这个特定衬线适合这个特定品牌
  * 对于其他所有情况（创意代理机构、设计工作室、现代品牌、高端消费级、作品集、生活方式），**默认无衬线展示字体**（Geist Display、ABC Diatype、Söhne Breit、Cabinet Grotesk Display、Migra Sans、GT Walsheim、Inter Display、PP Neue Montreal）。无衬线展示字体不是"无聊" - 它们是默认选择，原因和黑色是时尚界默认色一样。
  * **强调规则（相关）：** 当你想在标题中强调一个词（动态的"`spatial` 设计"那种效果）时，使用**同一字体的斜体或粗体**。绝不要为了增加视觉趣味而向无衬线标题中插入随机衬线词（反之亦然）。混合字体家族的强调是业余行为。同一家族内的斜体/粗体强调才是正确的做法。
  * **作为默认特别禁止：** `Fraunces` 和 `Instrument_Serif`（两个 LLM 最喜欢的展示衬线字体）。
  * **如果衬线有理由**（罕见，如上所述），从这个池中轮换使用，不要连续多个项目重复使用同一个衬线字体：PP Editorial New、GT Sectra Display、Cardinal Grotesque、Reckless Neue、Tiempos Headline、Recoleta、Cormorant Garamond、Playfair Display、EB Garamond、IvyPresto、Migra、Editorial Old、Saol Display、Söhne Breit Kursiv、Domaine Display、Canela、Schnyder、Tobias、NB Architekt、ITC Galliard。

* **斜体下缘清除（强制）：** 当展示字体使用斜体且该词包含下缘字母（`y g j p q`）时，`leading-[1]` 或 `leading-none` 会裁剪下缘。使用 `leading-[1.1]` 最小值并在包裹元素上添加 `pb-1` 或 `mb-1` 预留。在交付前审核展示标题中的每个斜体词。

### 4.2 配色校准
* 最多 1 个强调色。默认饱和度 < 80%。
* **LILA 规则：** "AI 紫色 / 蓝色发光"审美作为默认是不被推荐的。不要自动使用紫色按钮发光、随机霓虹渐变。使用中性基调（Zinc / Slate / Stone）+ 高对比度单一强调色（Emerald、Electric Blue、Deep Rose、Burnt Orange 等）。
* **覆盖：** 如果品牌或简报明确要求紫色 / 紫罗兰色 / LILA，就拥抱它。但要有意图地执行：一致的调色板、协调的中性色、克制的渐变。不是通用的 AI 渐变套话。
* **每个项目一个调色板。** 不要在同一项目中在暖色和冷色灰色之间波动。

* **配色一致性锁定（强制）：** 一旦为页面选择了强调色，它就用于整个页面。暖灰色网站不会在第 7 节突然出现蓝色 CTA。玫瑰色强调的网站不会在页脚出现青色状态徽章。选择一个强调色，锁定它，交付前审核每个组件。

* **高端消费级调色板禁令（强制，第二大 AI 特征）：**
  * 对于高端消费级简报（炊具、健康、手工艺、奢侈、传统工艺、DTC 家居用品等），LLM 默认是**暖米色/奶油色 + 黄铜/陶土/牛血色/赭石色 + 浓缩咖啡/墨色深色文字**。具体禁止作为默认背景和强调色的十六进制色系：
    - 背景：`#f5f1ea`、`#f7f5f1`、`#fbf8f1`、`#efeae0`、`#ece6db`、`#faf7f1`、`#e8dfcb`（全部是"暖纸 / 奶油 / 粉笔 / 骨白"）
    - 强调色：`#b08947`、`#b6553a`、`#9a2436`、`#9c6e2a`、`#bc7c3a`、`#7d5621`（全部是"黄铜 / 陶土 / 牛血 / 赭石"）
    - 文字：`#1a1714`、`#1a1814`、`#1b1814`（全部是"浓缩咖啡 / 暖近黑色"）
  * 这个调色板作为高端消费级简报的默认选择是**被禁止的**。你交付过的每个高端消费级网站都使用这个完全相同的调色板。品牌变得不可见。
  * **默认替代方案（轮换，不要重复使用）：**
    - **冷色奢华：** 银灰色 + 铬色 + 烟雾（想象 Tesla、Apple Watch Hermes 去掉皮革）
    - **森林：** 深绿色 + 骨白 + 琥珀色强调（想象 Filson、Patagonia 高端线）
    - **黑与棕：** 纯近黑色 + 暖棕，强烈对比，没有米色
    - **钴蓝 + 奶油色：** 高饱和蓝色对抗单一中性色，没有黄铜
    - **赤陶 + 石板灰：** 暖赭石对抗冷灰色，没有黄铜
    - **橄榄 + 砖红 + 纸张：** 柔和橄榄 + 砖红强调
    - **纯单色 + 单一高饱和亮点：** 灰白色 + 近黑色 + 一个亮色强调（电光蓝、翠绿色、亮粉色等）
  * **调色板轮换规则：** 如果你上一个生成的高端消费级项目使用了米色+黄铜家族，这个项目**必须**使用不同的家族。不要连续交付两次相同的暖色工艺调色板。
  * **覆盖：** 米色+黄铜+浓缩咖啡调色板仅在品牌简报明确命名这些颜色，或品牌身份确实是真正的复古 / 手工 / 暖色工艺且你能说明为什么这个特定调色板适合这个特定品牌时才是可接受的。因为"这是一个炊具简报"就默认选择它是被禁止的。

### 4.3 布局多样化
* **反中心偏差：** 当 `DESIGN_VARIANCE > 4` 时避免居中 Hero / H1 区域。强制使用"分屏"（50/50）、"左对齐内容 / 右对齐素材"、"非对称留白"或滚动固定结构。
* **覆盖：** 居中 Hero 对于编辑 / 宣言 / 发布公告类简报是可以的，因为信息本身就是设计。

### 4.4 材质感、阴影、卡片
* 仅在阴影传达真实层级时才使用卡片。否则使用 `border-t`、`divide-y` 或负空间分组。
* 使用阴影时，将其着色为背景色调。浅色背景上不要使用纯黑色投影。
* 当 `VISUAL_DENSITY > 7` 时：通用卡片容器被禁止。数据指标在纯布局中呼吸。
* **形状一致性锁定（强制）：** 为页面选择一个圆角大小体系并保持一致。选项：全锐角（radius 0）、全柔和（radius 12-16px）、全胶囊（交互元素全圆角）。仅当有记录规则（如"按钮是全胶囊，卡片是 16px，输入框是 8px"）且该规则处处遵守时，才允许混合体系。锐角布局中圆按钮、胶囊按钮页面上方形卡片是破碎的设计。

### 4.5 交互 UI 状态
LLM 默认为"仅有静态成功状态"。始终实现完整周期：
* **加载：** 与最终布局形状匹配的骨架加载器。避免通用圆形加载器。
* **空状态：** 精心构图；说明如何填充。
* **错误状态：** 清晰、内联（表单）或情境化（仅对瞬态错误使用 toast）。
* **触觉反馈：** 在 `:active` 时，使用 `-translate-y-[1px]` 或 `scale-[0.98]` 模拟物理按压。
* **按钮对比度检查（强制，无障碍）：** 在交付任何按钮之前，验证按钮文字在按钮背景上可读。白色按钮+白色文字、`bg-white` CTA 搭配 `text-white` 标签、透明按钮在页面背景上无边框 → 全部被禁止。审核每个 CTA：对比度满足 WCAG AA 最低标准（正文 4.5:1，大文字 18px+ 为 3:1）。相同的规则适用于摄影背景上的幽灵按钮（使用背景遮罩、蒙版或描边）。

* **CTA 按钮换行禁令（强制）：** 按钮文字在桌面端必须适合一行。如果标签如"查看精选作品"换行为 2 或 3 行，按钮是破损的。通过**缩短标签**（主 CTA 最多 3 个词， ideally 1-2 个）**或加宽按钮**（不要人为限制 CTA 的 `max-width`）来修复。桌面端换行的 CTA 是预检失败。

* **禁止重复 CTA 意图（强制）：** 一个页面上两个具有相同意图的 CTA 是预检失败。相同意图的示例："Get in touch" + "Contact us" + "Let's talk" + "Start a project" + "Start something" + "Reach out" = 全部是"联系"意图 → 选择一个标签并在页面上到处使用（导航、Hero、页脚）。"Try free" + "Get started" + "Sign up free"（全部是"注册"意图）和"View work" + "See selected work" + "Browse projects"（全部是"作品集"意图）同理。每个意图一个标签。

* **表单对比度检查（强制，无障碍）：** 表单输入框、占位文字、焦点环、帮助文字和错误文字都满足对区域背景的 WCAG AA 对比度。近白色表单上的浅色占位文字、白色页面区域上的白色表单、灰度低于 4.5:1 对比度的表单标签 → 全部被禁止。交付前审核每个表单。

### 4.6 数据与表单模式
* 标签在输入框**上方**。帮助文字可选但在标记中存在。错误文字在输入框**下方**。输入区块标准使用 `gap-2`。
* 永远不要用占位文字代替标签。

### 4.7 布局纪律（硬性规则。违反其中任何一条都是交付破损作品）

* **Hero 必须适配初始视口。** 标题在桌面端最多 2 行，副文本最多**20 个词**且最多 3-4 行，CTA 无需滚动即可看到。如果文案太长：减小字体大小或精简文案。如果你不能用 20 个词的副文本描述价值主张，那是价值主张不清晰，不是规则太紧。绝不要让 Hero 溢出并强制滚动才能找到 CTA。
* **Hero 字体缩放纪律。** 计划字体大小和图片大小**一起**。如果 Hero 素材很大且标题超过 6 个词，不要从 `text-7xl/text-8xl` 开始。默认合理范围：大多数 Hero 用 `text-4xl md:text-5xl lg:text-6xl`；仅在标题为 3-5 个词时用 `text-6xl md:text-7xl`。4 行 Hero 标题始终是字体大小错误，不是文案长度错误。
* **HERO 顶部内边距上限（强制）：** Hero 顶部内边距在桌面端最多 `pt-24`（约 6rem）。超过这个值意味着 Hero 内容浮动在视口一半处，看起来像布局 Bug，不是有意为之的留白。如果你的 Hero 需要更多呼吸空间，增加字体大小或素材大小，而不是顶部内边距。
* **HERO 堆栈纪律（最多 4 个文本元素）。** Hero 是一个时刻，不是特性列表。允许的文本元素，总共最多 4 个：
  1. 眉题（小号大写标签）或品牌条或都没有 - 选零个或一个
  2. 标题（最多 2 行，见上文）
  3. 副文本（最多 20 个词，最多 4 行）
  4. CTA（1 个主按钮 + 最多 1 个次按钮）
  - **Hero 中禁止的内容：** CTA 下方的小标语（"适用于 GitHub、GitLab 和自托管 Git"）、信任微条（"被以下工程团队使用..."）、定价预告（"个人免费，团队每人 $10"）、特性要点列表、社会证明头像行。所有这些东西移到 Hero 正下方的专属区域。
  - 如果你在同一个 Hero 中有眉题和 CTA 下方的小标语，删除小标语。如果你有品牌条和小标语，删除小标语。每个 Hero 一个小的文本元素，最多。
* **"Used by" / "Trusted by" logo 墙位于**Hero 下方，绝不在内部。** Hero 用于价值主张和主 CTA。Logo 墙是直接位于 Hero 下方的独立区域。不要将信任 logo 塞进与 Hero 文案相同的 flex 行中。
* **导航在桌面端必须渲染为单行。** 如果项目在 `lg`（1024px）处放不下，精简标签、删除次要项目或改为汉堡菜单。桌面端两行导航是破碎的设计。
* **导航高度上限：桌面端 80px 最大，默认 64-72px。** 不要有大号"代理机构"导航栏吃掉 15% 的视口。
* **Bento 网格必须有节奏，不是单边重复。** 不要堆叠 6 个左图 / 右文行。变化构图：交替全宽特性行、非对称磁贴大小、垂直中断。
* **BENTO 单元格数量规则（强制）：** Bento 网格的单元格数量恰好等于你有的内容数量。3 个项目 → 3 个单元格（1+2 分屏、2+1 或非对称三人组）。5 个项目 → 5 个单元格（2+3、3+2、hero+4 等）。如果你的网格中间或末尾有空单元格，你的规划有误。重新塑造网格；不要粘贴空白磁贴。
* **区块布局重复禁令。** 一旦你为一个区块使用了布局家族（如 3 列图片卡片、全宽引用、分屏图文），该家族在同一页面上最多出现**一次**。"精选委托作品"不应该看起来像"我们做什么"。一个有 8 个区块的落地页必须使用至少 4 个不同的布局家族。
* **之字形交替上限（强制）。** 交替的"左图+右文"然后"左文+右图"之字形布局 = 平庸。连续最多 2 个使用这种图文分屏模式的区块。连续第 3 个图文分屏是预检失败。用全宽区块、垂直堆叠区块、Bento 网格、跑马灯或不同的布局家族打破模式。
* **眉题克制（强制，生产测试中违反最多的规则）。** "眉题"是坐在区块标题上方的小号大写宽字距标签（如 `FOUR COLORWAYS`、`SELECTED WORK`、`THE HARDWARE`、`Git-native task management`）。典型 CSS 特征：`text-[11px] uppercase tracking-[0.18em]`、`font-mono text-[10.5px] uppercase tracking-[0.22em]`。每个 AI 构建的网站都在每个区块标题上方放眉题，产生相同的模板化节奏。硬性规则：
  - **每 3 个区块最多 1 个眉题。** Hero 算 1 个。所以一个有 9 个区块的页面总共最多使用 3 个眉题。
  - 如果区块 A 有眉题，接下来的 2 个区块不能有。
  - **预检检查是机械性的：** 统计所有区块组件中标题上方 `uppercase tracking`（或类似的小型大写单色标签）的出现次数。如果计数 > ceil(sectionCount / 3)，输出失败。
  - **眉题的替代做法：** 完全删除它。标题本身就足够了。如果你需要分类一个区块，区块在页面上的位置已经对它进行了分类；不需要标签。
* **分栏标题禁令（强制）。** 作为区块标题的"左侧大标题 + 右侧小说明段落"模式（左列占 7/8，右列占 4/5，一个小正文段落浮动在右列）**作为默认被禁止**。区块应该有一个焦点信息。如果你确实需要标题和说明段落，垂直堆叠它们（标题在上，正文在下，最大宽度 65ch）。仅在存在真正的构图原因时才选择分栏标题模式（例如，右列承载视觉或交互元素，不只是填充文字）。

* **Bento 背景多样性（强制）。** Bento 和特性网格区块不能是 6 个白底白字带文字的卡片。任何多单元格网格中至少有 2-3 个单元格需要真实的视觉变化：真实图片、品牌合适的渐变（不是 AI 紫色）、图案、着色背景。奶油色背景上奶油色卡片的 Bento 只有文字内容内部，即使页面其余部分很好，也读起来像无聊的 AI 默认。

* **移动端折叠必须对每个区块明确声明。** 对于每个多列布局，在同一组件中声明 `< 768px` 回退方案。不要有"没问题，Tailwind 会处理"的假设。

### 4.8 图片与视觉素材策略

落地页和作品集是**视觉产品**。只有文字的页面带假截图 div 是套话。

**视觉素材的优先级顺序：**
1. **优先使用图片生成工具。** 如果环境中任何图片生成工具都可用（`generate_image`、MCP 图片工具、IDE 集成生成、OpenAI 图片工具等），你必须使用它们来创建区块专属素材：Hero 摄影、产品照片、纹理背景、氛围图片。为区块生成正确的宽高比。不要跳过这一步因为手写 CSS 感觉更快。
2. **其次使用真实网络图片。** 当没有生成工具时，使用真实摄影来源。可接受的默认选项：
   - `https://picsum.photos/seed/{描述性种子}/{w}/{h}` 用于占位摄影（种子应该描述区块，如 `marrow-cookware-kitchen`）
   - 简报提供时的实际素材库或品牌 URL
   - 如果明确允许，使用开源来源（通过直接 URL 使用 Unsplash、Pexels）
3. **最后手段：告诉用户。** 如果都不可能，不要用页面填满手写 SVG 插图或 div 基础的"假截图。"相反，留下明确标记的占位槽（`<!-- TODO: hero 产品照片，1600x1200 -->`）并在响应末尾说：*"这个页面需要真实图片，位置在：[位置列表]。请生成或提供它们。"*

**即使是极简网站也需要真实图片。** 纯文字页面不是极简主义。它是不完整的工作。即使是编辑感 Linear 风格网站也需要至少 2-3 张真实图片（Hero、一张产品/生活照、一张辅助图片）。如果简报有节制，生成黑白极简摄影；不要因为旋钮低就完全跳过图片。

**社会证明用真实公司 logo。** 当简报要求"Trusted by / Used by / Customers" logo 墙时，不要默认为纯文字商标（`<span>Acme Co</span>` 在一行中样式化）。使用真实 SVG logo：
* **来源：Simple Icons**（`https://cdn.simpleicons.org/{slug}/ffffff` 用于任何颜色，或 `simple-icons` npm 包）。覆盖大多数知名品牌。
* **替代：devicon** 用于技术栈 logo（`@svgr/cli` 或 CDN）。
* **编造品牌名？那就也编造 SVG 标记。** 生成一个简单的字母组合（圆圈中的一个字母、两字母连字、抽象字形）渲染为与页面风格匹配的内联 `<svg>`。虚构品牌名的纯文字商标看起来通用。
* **始终**确保 logo 在浅色和深色模式下都正常渲染（深色背景上白色、浅色背景上黑色、或单色主题变量）。
* **仅 Logo 规则（强制）：** logo 墙 = logo 和其他什么都没有。不要在每个 logo 下方打印行业 / 类别标签（没有 `Vercel` + `hosting` 在下方，没有 `Stripe` + `payments`，没有 `Cloudflare` + `infra`）。Logo 是可信度，标签增加用户已经知道的东西。可选：用于屏幕阅读器的品牌名称作为 alt 文本，可选链接到品牌网站。仅此而已。

**手写插图：**
* 库中的 SVG 图标：可以（见第 3.C 节）。
* 手写装饰性 SVG（自定义插图、logo、标记）：**强烈不推荐**，绝不作为默认。仅在以下情况下可接受：
  - 简报明确要求（"给我画一个 SVG logo"）
  - 它是一个简单的几何标记（一个正方形、一个圆形、展示字体中的文字标记）
  - 你对输出质量有信心

**Div 基础的假截图被禁止。** 用 `<div>` 矩形、假任务列表、假仪表盘、假终端窗口渲染的"手工构建的产品预览"是一个特征。如果你需要展示产品：
* 使用真实截图 URL（如果存在）
* 通过图片工具生成一个
* 使用真实的组件预览（页面内的实际 UI 迷你版本）
* 或者完全跳过预览，使用编辑摄影

**Hero 需要真实视觉。** 文字 + 渐变斑点不是 Hero - 它是占位符。

### 4.9 内容密度

落地页依赖于**第一印象**，不是全文。 ruthless 地精简。

* **每个区块的默认内容形状：** 短标题（≤ 8 个词）+ 短副段落（≤ 25 个词）+ 一个视觉素材或一个 CTA。任何更多内容必须由区块的工作证明其合理性。
* **不要有数据倾倒区块。** 营销页面上的 20 行出版表、30 行奖项列表、巨大的定价矩阵 = 错误的布局。使用：
  - 前 3-5 个亮点 + "查看完整列表"链接
  - 用于广度的跑马灯 / 轮播
  - 如果数据是产品，就用不同的页面
* **长列表需要不同的 UI 组件，不是更长的列表。** 带项目符号 / `divide-y` 行的默认 `<ul>` 是偷懒的选择。如果你有 > 5 个项目，改用以下之一：
  - 2 列分屏，分组项目
  - 带图片 + 标签的卡片网格，每个项目一张
  - 标签页 / 手风琴（如果项目可分类）
  - 水平滚动吸附药丸
  - 用于广度重的列表的轮播（推荐语、logo、能力）
  - 用于"不需要 individually 关注的很多东西"的跑马灯
  - 带 10 行 + 每行下面一根毛发的规格表是最差的默认做法。要么将行分组为 2-3 个带稀疏分隔符的块，要么改为每张规格一张卡片的布局。
* **规格表特别说明（Marrow 炊具模式）。** 带有 `border-b` 在每一行的长产品规格表是 AI 对炊具 / 硬件 / 服装 / 手工艺品的简报默认做法。被禁止。具体替代方案：
  - **2 列卡片网格：** 每个规格都有自己的卡片，包含规格名称、值（大展示数字）和一个"为什么重要"的正文。桌面端 2 列排列，移动端 1 列。
  - **滚动吸附水平药丸：** 每个规格是一个药丸，用户可以滑动浏览。
  - **分组块：** 将 10 个规格分组为 3 个逻辑集群（如"材料"、"烹饪"、"保修"），每个集群获得一个柔和的软分隔符和集群标题。
  - **精选 vs 其余：** 3-4 个 hero 规格可视化作为大展示磁贴，其余折叠在"查看完整规格"的详情展开下。

* **文案自审（交付前强制）：** 在声明任何任务完成之前，重新阅读页面上的每个可见字符串（标题、副标题、眉题、按钮标签、正文、说明、alt 文本、页脚文字、错误信息）。标记任何字符串：
  - **语法破损**（"free on its past"、"two plans but one is honest"、"to put it on the table" 脱离上下文）
  - **指代不清**（"we plan to stay that way" 没有上下文）
  - **听起来像 AI 幻觉**（可爱但错误的文字游戏、不连贯的强制隐喻、"elegant nothing" 短语）
  - **读起来像 LLM 试图显得有思想**（被动攻击性的谦逊、假工匠标签、mock 诗意的微元语）
  重写每个被标记的字符串。如果不确定字符串是否通顺，用平淡的功能句替换。AI 生成的可爱文案比无聊的文案更糟糕。

* **虚假精确数字被标记。** 像 `92%`、`4.1×`、`48k`、`5.8 mm`、`13.4 lb` 这样的数字：
  - 来自真实数据（简报、品牌指南、公开指标）- 可以
  - 明确标记为模拟（`<!-- mock -->`、"example"、"sample data"）- 可以
  - 是 AI 发明的规格美学 - 被禁止。不要伪造品牌没有声称的工程精度。

* **每个页面一个文案基调。** 不要在同一构图中混合技术等宽（"47 tasks · 0.6 ctx-switches/day"）、编辑散文和营销 punch，除非品牌声音明确要求这样做。

### 4.10 引用与推荐语

* **引用正文最多 3 行。** 绝不要 6 行。如果原引用更长 → 精简。落地页引用是片段，不是完整评论。
* 对于非常小的字体大小（如页脚风格的推荐语），行长限制可以略微放宽。精神："一目了然。"
* **引用文字内禁止 em 破折号**作为设计装饰（长停顿、动态 em 破折号、em 破折号项目符号）。见第 9.G 节 - em 破折号完全被禁止。
* 署名：姓名 + 角色 + （可选）公司。不要只有姓名（"- Sarah"）。
* 引号：使用真实的排版引号（" "）或根本没有。不是直 ASCII（"）。

### 4.11 页面主题锁定（浅色 / 深色模式一致性）

页面有**一个**主题。区块不会反转。

* 如果页面是深色模式，**所有**区块都是深色模式。不要在深色区块之间插入浅色暖纸区块（反之亦然）。用户不应该感觉在滚动中途进入了不同的网站。
* 例外：如果简报明确要求"色块故事"或"滚动切换主题"机制且这是一个刻意的构图（一次完整的主题切换带有强烈的过渡，不是随机交替），每页允许一次。
* 默认行为：在页面级别选择浅色、深色或自动（`prefers-color-scheme`）并锁定。同一主题家族内的区块级背景色调是可以的（`bg-zinc-950` 旁边是 `bg-zinc-900`）；在 `bg-zinc-950` 页面中间切换到 `bg-amber-50` 是破碎的。
* 使用带有内置主题的设计系统（Radix Themes、shadcn/ui 带 `<Theme>`）时，在 `layout.tsx` 或页面根组件中设置一次主题。不要让单个区块覆盖。

## 5. 情境感知主动性

这些是工具，不是默认。在设计解读要求时使用它们。**没有任何一条会自动触发。**

* **Liquid Glass / 毛玻璃：** 适合高端消费级、Apple 相邻、奢侈品牌或媒体覆盖氛围。不适合仪表盘、公共部门或"无聊 B2B"。使用时，超越 `backdrop-blur`：添加 1px 内边框（`border-white/10`）和微妙的内阴影（`shadow-[inset_0_1px_0_rgba(255,255,255,0.1)]`）用于物理边缘折射。在 `prefers-reduced-transparency` 下提供纯色填充回退。
* **磁性微物理：** 当 `MOTION_INTENSITY > 5` 且简报解读为高端 / 活泼 / 代理机构时使用。**仅**使用 Motion 的 `useMotionValue` / `useTransform` 在 React 渲染周期之外实现。绝不要使用 `useState`。见第 3.B 节。
* **持续微交互**（脉冲、打字机、浮动、闪烁、轮播）：当 `MOTION_INTENSITY > 5` 且区块真正受益于动效时使用（状态指示器、实时信息流、AI 感）。**不是每张卡片都需要无限循环。** 如果区块是信息性的，保持静止。使用弹簧物理（`type: "spring", stiffness: 100, damping: 20`）- 不要使用线性缓动。
* **"声称有动效，就展示动效。"** 如果 `MOTION_INTENSITY > 4`，页面必须实际动起来：Hero 的入场过渡、关键区块的滚动揭示、CTA 的悬停物理，至少这些。一个声称 `MOTION_INTENSITY: 7` 的静态页面是破损的。反过来，如果你在可用范围内无法交付工作的动效，将旋钮降到 3 并交付干净的静态页面。绝不要半构建会出问题的动效（截断的 ScrollTrigger、跳动的入场、缺失的清理）。
* **动效必须有动机（强制）。** 在添加任何动画之前，问："这个动画传达什么？" 有效答案：层级（吸引注意力到正确的地方）、叙事（按与叙事匹配的顺序揭示内容）、反馈（确认用户操作）、状态转换（显示某些东西改变了）。无效答案："看起来很酷"。因为 GSAP 可用就在到处使用 GSAP 是业余行为。每个 ScrollTrigger、每个跑马灯、每个固定区块都需要理由。如果你不能用一句话说明理由，删除动画。

* **跑马灯每页最多一个（强制）。** 水平滚动文字跑马灯（"logo 无限滚动"、"宣言侧向滚动"、"动态文字条"）每页最多出现一次。同一页面上两个或更多跑马灯读起来像偷懒的填充物。选择一个跑马灯真正服务于内容的区块；其他的用不同的布局。

* **GSAP 粘性堆叠模式（使用滚动堆叠时）。** "滚动卡片堆叠"必须是真正的粘性堆叠，不是顺序揭示列表。见第 5.A 节的标准代码骨架。常见失败：触发器在滚动中途触发而不是在视口顶部固定。修复：`start: "top top"` 不是 `start: "top center"` 或 `"top 80%"`。

* **GSAP 水平平移模式（使用水平滚动劫持时）。** 见第 5.B 节的标准骨架。常见失败：动画在区块固定之前开始，所以用户看到了一半幻灯片。同样的修复：`start: "top top"`，固定包裹容器，scrub 内部轨道。

### 5.A 粘性堆叠 - 标准骨架

```tsx
"use client";
import { useRef, useEffect } from "react";
import { gsap } from "gsap";
import { ScrollTrigger } from "gsap/ScrollTrigger";
import { useReducedMotion } from "motion/react";

gsap.registerPlugin(ScrollTrigger);

export function StickyStack({ cards }: { cards: React.ReactNode[] }) {
  const ref = useRef<HTMLDivElement>(null);
  const reduce = useReducedMotion();

  useEffect(() => {
    if (reduce || !ref.current) return;
    const ctx = gsap.context(() => {
      const cardEls = gsap.utils.toArray<HTMLElement>(".stack-card");
      cardEls.forEach((card, i) => {
        if (i === cardEls.length - 1) return;
        ScrollTrigger.create({
          trigger: card,
          start: "top top",                              // 在视口顶部固定
          endTrigger: cardEls[cardEls.length - 1],
          end: "top top",
          pin: true,
          pinSpacing: false,
        });
        gsap.to(card, {
          scale: 0.92,
          opacity: 0.55,
          ease: "none",
          scrollTrigger: {
            trigger: cardEls[i + 1],
            start: "top bottom",
            end: "top top",
            scrub: true,
          },
        });
      });
    }, ref);
    return () => ctx.revert();
  }, [reduce]);

  return (
    <div ref={ref} className="relative">
      {cards.map((card, i) => (
        <div
          key={i}
          className="stack-card sticky top-0 min-h-[100dvh] flex items-center justify-center"
        >
          {card}
        </div>
      ))}
    </div>
  );
}
```

关键点：`start: "top top"`，`pin: true`，除最后一个外的每个卡片都被固定，scale/opacity 变换由**下一个**卡片的滚动触发器驱动（所以前一张卡片在下一张到达时缩小）。

### 5.B 水平平移 - 标准骨架

```tsx
"use client";
import { useRef, useEffect } from "react";
import { gsap } from "gsap";
import { ScrollTrigger } from "gsap/ScrollTrigger";
import { useReducedMotion } from "motion/react";

gsap.registerPlugin(ScrollTrigger);

export function HorizontalPan({ children }: { children: React.ReactNode }) {
  const wrap = useRef<HTMLDivElement>(null);
  const track = useRef<HTMLDivElement>(null);
  const reduce = useReducedMotion();

  useEffect(() => {
    if (reduce || !wrap.current || !track.current) return;
    const ctx = gsap.context(() => {
      const distance = track.current!.scrollWidth - window.innerWidth;
      gsap.to(track.current, {
        x: -distance,
        ease: "none",
        scrollTrigger: {
          trigger: wrap.current,
          start: "top top",                              // 当区块顶部到达视口顶部时开始固定
          end: () => `+=${distance}`,                    // 滚动距离 = 轨道宽度减去视口宽度
          pin: true,
          scrub: 1,
          invalidateOnRefresh: true,
        },
      });
    }, wrap);
    return () => ctx.revert();
  }, [reduce]);

  return (
    <section ref={wrap} className="relative overflow-hidden">
      <div ref={track} className="flex h-[100dvh] items-center">
        {children}
      </div>
    </section>
  );
}
```

关键点：`start: "top top"`，`pin: true`，`end: "+=${distance}"`（滚动长度 = 水平移动所需距离），`scrub: 1`。包裹容器被固定，内部轨道随着用户垂直滚动而水平滑动。

### 5.C 滚动揭示交错 - 标准骨架（更轻量的替代方案）

对于简单的"项目进入视口时出现"（不需要固定），优先使用 Motion 的 `whileInView` 而非 GSAP - 更轻量，不需要 ScrollTrigger：

```tsx
"use client";
import { motion, useReducedMotion } from "motion/react";

export function RevealStagger({ items }: { items: string[] }) {
  const reduce = useReducedMotion();
  return (
    <ul className="grid gap-6">
      {items.map((item, i) => (
        <motion.li
          key={item}
          initial={reduce ? false : { opacity: 0, y: 24 }}
          whileInView={{ opacity: 1, y: 0 }}
          viewport={{ once: true, amount: 0.3 }}
          transition={{
            duration: 0.6,
            delay: i * 0.06,
            ease: [0.16, 1, 0.3, 1],
          }}
        >
          {item}
        </motion.li>
      ))}
    </ul>
  );
}
```

适用场景：特性列表、推荐语网格、logo 墙，任何只需要"滚动进入"效果的东西。将 GSAP 留给真正的固定 / scrub 工作。

### 5.D 禁止的动画模式

* **`window.addEventListener("scroll", ...)`** 被禁止。它在每个滚动帧运行，容易卡顿，没有批处理。使用 Motion 的 `useScroll()`、GSAP 的 `ScrollTrigger`、IntersectionObserver 或 CSS `scroll-driven animations`（`animation-timeline: view()`）。
* React 状态中使用 `window.scrollY` 进行自定义滚动进度计算。同样的原因。在每一帧重新渲染。
* 接触 React 状态的 `requestAnimationFrame` 循环。使用运动值（`useMotionValue` + `useTransform`）代替。
* **布局过渡：** 使用 Motion 的 `layout` 和 `layoutId` prop 处理可见状态变化（重新排序列表、展开模态框、路由之间的共享元素）。不要将静态内容包裹在 `layout` prop 中"为了安全" - 它需要测量工作。
* **交错编排：** 使用 `staggerChildren`（Motion）或 CSS 级联（`animation-delay: calc(var(--index) * 100ms)`）处理顺序重要的揭示时刻。对于 `staggerChildren`，父级（`variants`）和子级必须在同一个 Client Component 树中共享。

## 6. 性能与无障碍保障

### 6.A 硬件加速
* 仅动画化 `transform` 和 `opacity`。绝不动画化 `top`、`left`、`width`、`height`。
* 谨慎使用 `will-change: transform` - 仅在实际会动画化的元素上使用。

### 6.B 减少动效（强制）
* 任何 `MOTION_INTENSITY > 3` 的动效**必须**尊重 `prefers-reduced-motion`。这是不可协商的。
* 在 Motion 中：用 `useReducedMotion()` 包裹并降级为静态。
* 在 CSS 中：将动画限制在 `@media (prefers-reduced-motion: no-preference)` 后面，或在 `@media (prefers-reduced-motion: reduce)` 下提供禁用动画的覆盖块。
* 无限循环、视差、滚动劫持和磁性物理效果在减少动效下必须折叠为静态 / 即时。

### 6.C 深色模式（面向消费者的任何页面都强制）
* **从开始就设计两种模式。** 绝不在没有明确用户指令的情况下交付仅浅色或仅深色的页面。
* 使用 Tailwind `dark:` 变体或 CSS 变量作为 token。每个项目选择一个策略。
* **不要在这里规定具体的深色模式颜色。** 简报决定。在两种模式下保持视觉层级、品牌身份和 WCAG AA 对比度（正文为 AAA）。
* 尊重 `prefers-color-scheme: dark`。默认跟随系统偏好，除非品牌坚持单一模式。

### 6.D Core Web Vitals 目标
* **LCP** < 2.5s。Hero 图片必须是 `next/image priority` 或预加载。
* **INP** < 200ms。繁重工作移出主线程。
* **CLS** < 0.1。为图片、字体、嵌入内容预留空间。
* 在声明页面完成之前运行 Lighthouse。

### 6.E DOM 成本
* 将颗粒 / 噪点滤镜**仅**应用于固定的、`pointer-events-none` 伪元素（如 `fixed inset-0 z-[60] pointer-events-none`）。绝不应用于滚动容器 - 持续的 GPU 重绘会破坏移动端 FPS。
* 注意包大小。Motion 不小。Three.js 很大。懒加载所有非首屏内容。

### 6.F Z-Index 克制
绝不滥用任意的 `z-50` 或 `z-10`。严格将 z-index 用于系统性层级上下文（粘性导航栏、模态框、覆盖层、颗粒）。在项目常量文件中记录 z-index 体系。

## 7. 旋钮定义（技术参考）

### DESIGN_VARIANCE（等级 1-10）
* **1-3（可预测）：** 对称 CSS Grid（12 列、相等的 fr 单位）、相等的内边距、居中对齐。
* **4-7（偏移）：** `margin-top: -2rem` 重叠、不同的图片宽高比（4:3 旁边是 16:9）、居中对齐数据上方的左对齐标题。
* **8-10（非对称）：** 瀑布流布局、带分数单位的 CSS Grid（`grid-template-columns: 2fr 1fr 1fr`）、巨大的空白区域（`padding-left: 20vw`）。
* **移动端覆盖：** 对于等级 4-10，`md:` 以上的非对称布局在视口 `< 768px` 上必须折叠为严格单列（`w-full`、`px-4`、`py-8`）。

### MOTION_INTENSITY（等级 1-10）
* **1-3（静态）：** 无自动动画。仅 CSS `:hover` 和 `:active` 状态。`prefers-reduced-motion` 本身就是默认模式。
* **4-7（流畅 CSS）：** `transition: all 0.3s cubic-bezier(0.16, 1, 0.3, 1)`。加载时的 `animation-delay` 级联。专注于 `transform` 和 `opacity`。
* **8-10（高级编排）：** 复杂的滚动触发揭示、视差、滚动驱动动画（CSS `animation-timeline` 或 GSAP ScrollTrigger）。使用 Motion 钩子。**绝不使用 `window.addEventListener('scroll')`** - 这是硬性禁令，不是"最好不"。见第 5.D 节的允许替代方案。

### VISUAL_DENSITY（等级 1-10）
* **1-3（艺术画廊）：** 大量留白。巨大的区块间距（`py-32` 到 `py-48`）。昂贵、干净。
* **4-7（日常应用）：** 标准 Web 应用间距（`py-16` 到 `py-24`）。
* **8-10（仪表盘）：** 紧密的内边距。没有卡片盒；1px 线分隔数据。强制要求：所有数字使用 `font-mono`。

## 8. 深色模式协议

默认双模式。除非简报是模拟印刷的编辑风格，否则不要假设仅浅色。

### 8.A Token 策略（选一个，坚持它）
* **Tailwind `dark:` 变体**（工具类优先项目的默认）：每个颜色工具类配对其深色变体（`bg-white dark:bg-zinc-950`、`text-gray-900 dark:text-gray-100`）。
* **CSS 变量**（用于 shadcn/ui、Radix Themes 或有主题的组件库）：定义语义 token（`--surface`、`--surface-elevated`、`--text-primary`、`--accent`）并在 `[data-theme="dark"]` 或 `@media (prefers-color-scheme: dark)` 下交换值。

### 8.B 不要在这里规定具体颜色
简报和品牌决定。本技能仅强制执行：
* **对比度** - 正文 WCAG AA 最低标准，Hero 文案 AAA 目标。
* **层级对等** - 浅色模式有效的视觉层级在深色模式也必须有效。如果 CTA 在浅色模式突出，它在深色模式也必须突出。
* **品牌忠实度** - 主品牌颜色保持可识别。不要在深色模式中把品牌去饱和。
* **不要用纯 `#000000` 和纯 `#ffffff`** - 使用近黑色（zinc-950、暖灰色近黑色）和灰白色。纯值会杀死深度。

### 8.C 默认模式
尊重 `prefers-color-scheme`，除非品牌坚持。如果任一模式会丢失关键品牌表达，添加手动切换。

### 8.D 完成前在两种模式下测试
在开发过程中用两种模式打开页面。不要交付你只在一种模式下看过的页面。

## 9. AI 特征（禁止模式）

除非简报明确要求，否则避免这些特征。

### 9.A 视觉与 CSS
* **默认不用霓虹 / 外部发光。** 使用内边框或微妙着色阴影。
* **不用纯黑色（`#000000`）。** 使用近黑色、zinc-950 或炭灰色。
* **不要过度饱和的强调色。** 去饱和以与中性色融合。
* **大标题不要过多的渐变文字。**
* **不要自定义鼠标光标。** 过时、无障碍不友好、性能不友好。

### 9.B 字体排版
* **避免默认使用 Inter。** 见第 4.1 节。存在覆盖路径。
* **不要 oversized 的 H1** 只是在大喊。用字重 + 颜色控制层级，不是原始尺寸。
* **衬线限制：** 衬线用于编辑 / 奢侈 / 出版。不用于仪表盘。

### 9.C 布局与间距
* **数学上完美**的内边距和外边距。不要有 awkward 间隙的浮动元素。
* **不要 3 列相同的特性卡片。** 通用的"三个相同卡片水平排列"特性行被禁止。使用 2 列之字形、非对称网格、滚动固定或水平滚动替代方案。

### 9.D 内容与数据（"Jane Doe"效应）
* **不要通用名称。** "John Doe"、"Sarah Chan"、"Jack Su" → 使用有创意的、真实的、符合地域的名称。
* **不要通用头像。** 没有 SVG"蛋"或 Lucide 用户图标 → 使用可信的照片占位符或特定样式。
* **不要虚假完美的数字。** 避免 `99.99%`、`50%`、`1234567`。使用有机的、 messy 的数据（`47.2%`、`+1 (312) 847-1928`）。
* **不要创业套话品牌名。** "Acme"、"Nexus"、"SmartFlow"、"Cloudly" → 发明符合上下文的、高端的听起来真实的名称。
* **不要填充动词。** "Elevate"、"Seamless"、"Unleash"、"Next-Gen"、"Revolutionize" → 只用具体动词。

### 9.E 外部资源与组件
* **不要手写 SVG 图标。** 使用 Phosphor / HugeIcons / Radix / Tabler。仅在明确要求时使用 Lucide。
* **不推荐手写装饰性 SVG** 作为默认（见第 4.8 节）。
* **不要 div 基础的假截图。** 绝不要用 `<div>` 矩形构建假产品 UI 来模拟截图。使用真实图片、生成的图片，或完全跳过预览。
* **不要破损的 Unsplash 链接。** 使用 `https://picsum.photos/seed/{描述性字符串}/{w}/{h}`，或生成的摄影占位符，或实际素材。
* **shadcn/ui 定制：** 允许，但绝不使用默认状态。定制圆角、颜色、阴影、字体排印以匹配项目审美。
* **生产就绪的整洁度：** 代码视觉整洁、令人难忘、 meticulously 精致。

### 9.F 生产测试特征（ outright 禁止）

这些模式来自真实的 LLM 生成落地页测试。它们是模型试图"看起来设计过"时的默认签名。除非简报明确要求，否则将其视为硬性禁令。

**Hero 和页面顶部**
* **Hero 中不要版本标签。** `V0.6`、`v2.0`、`BETA`、`INVITE-ONLY PREVIEW`、`EARLY ACCESS`、`ALPHA` - 作为默认眉题被禁止。仅在简报明确关于产品发布 / 预览状态时可接受。
* **不要"Brand · No. 01"风格的子眉题。** "Marrow · No. 01 · The 6-quart"类型的微元语行。跳过它们。

**区块编号和微标签**
* **不要区块编号眉题。** `00 / INDEX`、`001 · Capabilities`、`002 · Featured commission`、`06 · how it works`、`05 · The honest table` - 被禁止。眉题应该用普通语言命名主题，而不是列举。
* **不要在图片或 Bento 磁贴上有 `01 / 4` 风格的翻页标签。** 如果用户可以数，他们不需要标签。
* **不要 `Scroll · 001 Capabilities` 风格的滚动提示。** 简单的箭头或"Scroll"就够了；不需要区块编号前缀。
* **不要"Index of Work, 2018 - 2026"风格的范围标签**作为眉题。直接说区块是什么。

**分隔符和点**
* **中间点（`·`）定量配给。** 元数据条中每行最多 1 个。不要把它作为所有东西的默认分隔符（"foo · bar · baz · qux · quux"）。如果你需要分隔符系列，更喜欢换行、细线或列。
* **不要在每个列表/导航/徽章上有装饰性彩色状态点。** "ONE Q4 SLOT OPEN" 前面的彩色点，或每个导航链接前、或每个任务行前 - 默认被禁止。仅当点传达实际的语义状态（服务器状态、可用性标志）且谨慎使用时才可接受。

**Em 破折号和字体装饰**
* **不要将 em 破折号（`—`）作为设计元素或任何其他地方使用。** 见第 9.G 节以下的完整、不可协商的禁令。em 破折号字符在标题、眉题、药丸、正文、引用、署名、说明、按钮文字和 alt 文字中被禁止。使用常规连字符（`-`）。
* **不要将 `<br>` 分隔和斜体化标题作为默认"设计手法"。** "for thirty\<br\>*years.*" 类型的分割。标题应该首先自然可读，仅在简报要求时才变聪明。
* **不要垂直旋转文字**（"INDEX OF WORK, 2018 - 2026"旋转 90°）。代理机构作品集陈词滥调。仅在简报明确是代理机构 / Awwwards / 实验性且它服务于真正的构图目的时才使用。
* **不要十字准星 / 细线网格线作为装饰。** 仅仅为了使页面"感觉设计过"而绘制的垂直和水平线 - 被禁止。仅在它们组织真实内容时才使用。

**假产品预览**
* **Hero 中不要 div 基础的假产品 UI**（假任务列表、假终端、假仪表盘用样式化 div 构建）。它是排名第一的 LLM 设计特征。使用真实截图、生成的图片、真实的组件预览，或根本没有。
* **不要假版本页脚**（"v0.6.2-rc.1"、"last sync 4s ago · main"）在假截图内。没有任何价值， screaming AI。

**营销文案特征**
* **不要"Quietly in use at" / "Quietly trusted by"** 社会证明标题。使用自然语言："Trusted by"、"Used at"、"Customers include"，或者如果 logo 自己说话就完全跳过标题。
* **不要"From the field" / "Field notes" / "Currently on the bench" / "On our desks" / "Loose plates"** 风格的诗意标签在引用、博客或侧边栏区块上。读起来像表演工匠。使用平淡的功能标签（"Testimonials"、"Latest writing"、"Now working on"）或跳过标签。
* **不要正文中"我们尊重法国人"风格的** mock 谦逊行业引用。可爱且 AI 感。
* **不要天气 / 地点条**（"LIS 14:23 · 18°C"）在页眉/页脚中，除非简报明确关于一个地方 / 时区分销的工作室。
* **不要在眉题下有微元语句。** 像 *"这些每一个都是我们今天交付的功能，不是路线图承诺。列表会故意保持简短。"* 坐在区块标题下方的句子是 clutter。眉题 + 标题 + 正文就足够了。
* **不要通用步骤标签。** "Stage 1 / Stage 2 / Stage 3"、"Step 1 / Step 2 / Step 3"、"Phase 01 / Phase 02 / Phase 03"、"Pass One / Pass Two / Pass Three"。被禁止。实际的步骤内容是标签。如果你必须展示进展，直接使用动词-名词（"Install"、"Configure"、"Ship"）而不是"Stage 1: Install"。

**药丸、标签和版本印章**
* **不要在图片上叠加药丸/标签/标签。** 没有带有 `Brand · 02`、`PLATE · BRAND`、`Field notes - journal` 等标签的 `<span>` 图片叠加层。要么让图片自己说话，要么直接在图片下方添加说明（图片外部）。
* **不要把照片信用说明作为装饰。** 像 `Field study no. 12 · Ines Caetano`、`Plate 03 · House archive`、`Frame XII · 35mm` 这样的字符串在库存 / picsum 图片下方是自命不凡的。照片信用仅在有一个真实摄影师为真实照片署名（有许可）时才被允许。否则：跳过说明或使用单行功能说明（"6-quart，Sage 色。"）。
* **营销页面上不要版本页脚。** `v1.4.2`、`Build 0048`、`last sync 4s ago · main` 这样的页脚字符串是 CLI / 开发工具夹具，不是落地页内容。营销/落地/作品集页面被禁止。
* **不要"Reservation 412 of 800"风格的实时库存计数器**作为装饰。仅当简报明确是有真实数据的限量候补名单时才可接受。

**装饰文字条**
* **不要在 Hero 底部放装饰文字条。** 像 `BRAND. MOTION. SPATIAL.`、`TYPE / FORM / MOTION`、`DESIGN · BUILD · SHIP`、`ESTD. 2018 · LISBON · BRAND. MOTION. SPATIAL.` 作为横跨 Hero 底部的小型单色大写条是代理机构作品集陈词滥调。默认被禁止。仅当条带承载真实可导航的链接（粘性底部导航）或真实状态信息（cookie 横幅、文档站点上的构建信息）时才可接受。
* **不要在区块标题中有浮动右上角子文字。** 模式：区块有一个巨大的左对齐标题；在同一区块标题的右上角有一个小说明段落，与任何其他东西没有清晰对齐。那个浮动物就是特征。要么将子文字直接放在标题下方，要么构建一个干净的 2 列标题（左：标题，右：对齐正文），但不是一个微小的角落段落。

**列表、分隔符和评分**
* **不要长列表 / 规格表的每一行都有 `border-t` + `border-b`。** 选一个（行间下边框或组上边框）并稀疏使用。一个带每行毛发的 10 行规格表是最偷懒的布局 - 见第 4.9 节替代 UI 组件。
* **不要用填充背景轨道的评分/进度条**作为比较视觉效果。如果你需要展示"X 对 Y"比较，优先使用数字 + 小图标，或没有背景轨道的小型内联条。大填充的 `bg-zinc-200` 轨道上方有部分填充是落地页上的仪表盘 UI clutter。

**地域、时间、滚动提示**
* **地域 / 城市名 / 时间 / 天气条对 99% 的简报被禁止。** Hero 中的"Lisbon, working with founders"、页脚中的"1200-690 Lisbon, Portugal"、导航中的"Lisbon 14:23 · 18°C"。这些是代理机构作品集装饰特征。仅在以下情况允许：简报明确描述具有时区相关工作的全球分布工作室，或旅游导向品牌，或真实世界实体场馆。页脚中的单一联系地址提及是可以的；氛围性地域条不是。
* **滚动提示被禁止。** `Scroll`、`↓ scroll`、`Scroll to explore`、`Scroll to walk through it`、动画鼠标滚轮图标。如果用户还没有滚动，他们正在看 Hero。他们知道什么是滚动。视口底部不需要标签。
* **默认零装饰状态点。** 导航项、列表行、徽章、状态标签前的彩色点是特征。仅当传达真实的语义状态（真实服务器状态上的实时指示器、实时可用性标志）且每页区块最多一个时才可接受。

### 9.G EM 破折号禁令（违反最多的特征）

**Em 破折号（`—`）完全被禁止。** 它是 LLM 的标志性风格拐杖，是生产测试中排名第一的视觉特征。没有"有限使用"的容限，没有"自然语言频率"的容限，没有"正文中可以"的容限。没有。

* **标题中被禁止。** 使用句号或逗号。
* **眉题 / 标签 / 药丸 / 按钮文字 / 图片说明 / 导航项中被禁止。** 用换行、列或细线替换。
* **正文中被禁止。** 重构句子：用句号的两个句子，或逗号，或括号，或冒号。
* **引用署名中被禁止。** 使用带空格的正则连字符（` - `）或换行 + 更小字重的名称。
* **en 破折号形式（`–`）作为分隔符时也被禁止。** 日期范围（`2018-2026`）使用连字符。数字范围（`€40-80k`）使用连字符。

页面上唯一允许的破折号字符是：
* 常规连字符 `-`（用于复合词、范围、标记中的行分隔符）
* 数学中的减号（`-5°C`）

如果你的输出中包含任何对用户可见的单个 `—` 或 `–`，输出预检失败且必须重写。

这个规则是不可协商的。当措辞为"谨慎使用"时，代理历史上会忽略 em 破折号限制。这里的措辞是二元的：零个 em 破折号。

## 10. 参考词汇（代理应该知道的模式名称）

这是一个词汇表，不是库。代理应该**知道**这些模式名称以便沟通、设计时考虑它们、并在设计解读要求时选用它们。**实现和代码草图位于区块库（第 12 节），以迭代方式填充。**

### Hero 范式
* **非对称分屏 Hero** - 一侧文字，一侧素材，generous 留白。
* **编辑宣言 Hero** - 大字体，无素材，近乎海报。
* **视频 / 媒体遮罩 Hero** - 文字作为视频背景上的遮罩切割出来。
* **动态字体 Hero** - 动态字体排印作为主要视觉。
* **帘幕揭示 Hero** - Hero 部分在滚动时像帘幕一样展开。
* **滚动固定 Hero** - Hero 保持固定，内容在后方滚动。

### 导航与菜单
* **Mac OS Dock 放大** - 边缘导航，图标在悬停时流畅缩放。
* **磁性按钮** - 向光标拉动。
* **粘性菜单** - 子项像粘性液体一样分离。
* **动态岛** - 用于状态 / 提醒的变形药丸。
* **情境径向菜单** - 在点击点展开的圆形菜单。
* **浮动快速拨号** - FAB 弹入弯曲的次要操作。
* **巨型菜单揭示** - 全屏下拉，交错淡入内容。

### 布局与网格
* **Bento 网格** - 非对称磁贴分组（Apple 控制中心）。
* **瀑布流布局** - 错开网格，无固定行高。
* **色度网格** - 带有微妙动画渐变的边框 / 磁贴。
* **分屏滚动** - 两半向相反方向滑动。
* **粘性堆叠区块** - 在滚动时固定并堆叠的区块。

### 卡片与容器
* **视差倾斜卡片** - 跟踪鼠标坐标的 3D 倾斜。
* **聚光灯边框卡片** - 边框在光标下点亮。
* **毛玻璃面板** - 带内部折射的磨砂玻璃。
* **彩虹箔卡片** - 悬停时虹彩彩虹偏移。
* **Tinder 滑动堆叠** - 物理卡片堆，滑动移除。
* **变形模态框** - 按钮扩展为自己的对话框。

### 滚动动画
* **粘性滚动堆叠** - 卡片固定并物理堆叠。
* **水平滚动劫持** - 垂直滚动 → 水平平移。
* **Locomotive / 序列滚动** - 视频 / 3D 序列与滚动条绑定。
* **缩放视差** - 中央背景图片在滚动时缩放。
* **滚动进度路径** - SVG 线条沿滚动绘制。
* **液体滑动过渡** - 页面过渡像粘性液体。

### 画廊与媒体
* **穹顶画廊** - 3D 全景画廊。
* **封面流轮播** - 带倾斜边缘的 3D 轮播。
* **拖拽平移网格** - 无限可拖动画布。
* **手风琴图片滑块** - 悬停时扩展的窄条。
* **悬停图片轨迹** - 鼠标离开弹出图片轨迹。
* **故障效果图片** - 悬停时 RGB 通道偏移。

### 字体排印与文字
* **动态跑马灯** - 滚动时反向的无限文字条。
* **文字遮罩揭示** - 作为视频透明窗口的大字体。
* **文字扰乱效果** - 加载 / 悬停时的 Matrix 风格解码。
* **圆形文字路径** - 文字沿旋转圆圈弯曲。
* **渐变描边动画** - 带运行渐变的轮廓文字。
* **动态字体网格** - 字母躲避光标。

### 微交互与效果
* **粒子爆炸按钮** - CTA 在成功时炸成粒子。
* **液体下拉刷新** - 像分离液滴的重载指示器。
* **骨架闪烁** - 跨占位符移动的光反射。
* **方向悬停感知按钮** - 填充从光标的精确侧进入。
* **涟漪点击效果** - 来自点击坐标的波浪。
* **动画 SVG 线条绘制** - 矢量实时绘制自己。
* **网格渐变背景** - 有机熔岩灯斑点。
* **镜头模糊深度** - 背景 UI 模糊以聚焦前景操作。

### 动画库选择
* **Motion（`motion/react`）** - UI / Bento / 状态变化动效的默认选择。
* **GSAP + ScrollTrigger** - 全页滚动叙事和滚动劫持。在带 `useEffect` 清理的专用叶子组件中隔离。
* **Three.js / WebGL** - 画布背景和 3D 场景。相同的隔离规则。
* **绝不在同一个组件树中混合 GSAP / Three.js 与 Motion。** 它们争夺相同的帧。

## 11. 重构协议

本技能处理**全新构建和重构**。错误分类模式是糟糕重构输出的最大来源。

### 11.A 检测模式（第一个动作）
* **全新构建** - 没有现有网站，或全面改造已获批准。从第 1 节获取旋钮基准值。
* **重构 - 保留** - 现代化而不破坏品牌。先审核，提取品牌 token，逐步演变。
* **重构 - 全面改造** - 现有内容上的新视觉语言。视觉上当作全新构建处理；保留内容和 IA。

如果模糊，问**一次**：*"这个重构应该保留现有品牌，还是我们从视觉上从头开始？"*

### 11.B 在触碰之前先审核
在提出更改之前记录当前状态：
* **品牌 token** - 主色 / 强调色、字体堆栈、logo 处理、圆角。
* **信息架构** - 页面树、主导航、关键转化路径。
* **内容区块** - 存在什么、什么在工作、什么是填充物。
* **要保留的模式** - 标志性交互、可识别的 Hero、文案声音。
* **要淘汰的模式** - AI 套话特征、破碎布局、死链接、通用库存图片、性能陷阱。
* **现有网站的旋钮解读** - 推断当前的 `DESIGN_VARIANCE` / `MOTION_INTENSITY` / `VISUAL_DENSITY`。那是你的起点，不是基准值。
* **SEO 基准** - 当前排名页面、meta 标题、结构化数据、OG 卡片。**SEO 迁移是排名第一的重构风险。**

### 11.C 保留规则
* **除非被要求，否则不要更改信息架构。** 为了 SEO 和肌肉记忆，保持页面 slug、锚点 ID、主导航标签稳定。
* **在应用第 4.2 节之前提取品牌颜色。** 已经是紫色的品牌保持紫色 - 应用 LILA 规则的覆盖。
* **除非被要求重写，否则保留文案声音。** 视觉现代化 ≠ 内容重写。
* **尊重现有的无障碍成果。** 不要回退焦点状态、alt 文本、键盘导航、对比度。
* **尊重现有的分析事件。** 不要重命名下游跟踪依赖的按钮、表单字段、区块 ID。

### 11.D 现代化杠杆（优先级顺序）
按顺序应用 - 当简报满意时停止：
1. **字体排印刷新** - 每单位风险的最大视觉提升。
2. **间距与节奏** - 增加区块内边距，修复垂直节奏。
3. **颜色重新校准** - 去饱和，统一中性色，保留品牌强调色。
4. **动效层** - 向现有组件添加 `MOTION_INTENSITY` 合适的微交互。
5. **Hero 和关键区块重组** - 使用第 10 节词汇重构漏斗顶部。
6. **完整区块替换** - 仅当现有区块无法挽救时。

### 11.E 决策树：定向演变 vs 全面重构
* IA、内容和 SEO 听起来不错 → **定向演变**（杠杆 1-4）。约 70% 的价值，约 40% 的风险。
* 视觉债务是结构性的（破碎的 IA、没有设计系统、破碎的移动端） → **全面重构**，严格保留内容。
* 品牌本身在变化 → **全新构建**。

### 11.F 什么永远静默不变更
未经用户明确批准绝不要修改：
* URL 结构 / 路由 slug。
* 主导航标签。
* 表单字段名称或顺序（破坏分析 + 自动填充）。
* 品牌 logo 或文字商标。
* 现有法律 / 同意 / cookie 文案。

### 12.C 必需的正文区块
1. **视觉草图** - 布局的简短 ASCII 或描述。
2. **Props API** - 组件的接口。
3. **代码草图** - 最小可行实现（Server Component 默认，动效用 Client island）。
4. **移动端回退** - `< 768px` 的明确折叠规则。
5. **动效变体** - 每个 `MOTION_INTENSITY` 频段一个变体（1-3、4-7、8-10）。减少动效回退明确。
6. **深色模式说明** - 特定于此区块的 token 策略。
7. **反模式** - 此区块出错的常见方式。
8. **参考** - 生产环境中真实示例的链接。

### 12.D 区块库纪律
* 每个文件一个区块。没有多区块文件。
* 每个区块必须独立工作（丢入页面，它渲染）。
* 每个区块必须通过预检（第 14 节）。
* 依赖第 2.A 节设计系统的区块位于 `blocks/<category>/<name>--<system>.md`（如 `feature/bento-grid--material.md`）。

## 附录 C - Apple Liquid Glass：诚实的 Web 近似方案

不要将随机的 CSS 代码片段视为官方 Apple Liquid Glass。

### 什么是官方的
Apple 在 Apple 的《人机界面指南》和《开发者文档》中记录了 Liquid Glass，适用于**Apple 平台**。它是 Apple 平台 UI 中使用的动态材质。Apple 的原生实现属于 Apple 平台 API 和系统组件，**不是公开的 Web CSS 包**。

相关官方文档：
- Apple 人机界面指南 → 材质
- Apple 开发者文档 → Liquid Glass
- Apple 开发者文档 → 采用 Liquid Glass
- SwiftUI → Material

### 什么不是官方的
Apple 没有为普通网站提供 `liquid-glass.css`。

Web 近似方案可以使用：
- `backdrop-filter`
- 透明背景
- 分层边框
- 高光叠加层
- 渐变
- 动效
- 强对比度回退

但那是**Web 毛玻璃 / 磨砂玻璃近似方案**，不是官方 Apple Liquid Glass。在注释中将其标记为此类。

### 更安全的 Web 近似方案骨架

```css
/* Web 毛玻璃近似方案 — 非 Apple 官方 Liquid Glass */
.liquid-glass-web-approx {
  position: relative;
  isolation: isolate;                        /* 创建独立层叠上下文 */
  overflow: hidden;
  border-radius: 999px;
  border: 1px solid rgb(255 255 255 / .32);  /* 半透明白色边框，模拟边缘折射 */
  background:
    linear-gradient(135deg, rgb(255 255 255 / .30), rgb(255 255 255 / .08)), /* 高光渐变 */
    rgb(255 255 255 / .12);                  /* 半透明基底 */
  backdrop-filter: blur(24px) saturate(180%) contrast(1.05);  /* 毛玻璃核心效果 */
  -webkit-backdrop-filter: blur(24px) saturate(180%) contrast(1.05); /* Safari 兼容 */
  box-shadow:
    inset 0 1px 0 rgb(255 255 255 / .48),   /* 顶部内高光，模拟光线折射 */
    inset 0 -1px 0 rgb(255 255 255 / .12),  /* 底部内阴影 */
    0 18px 60px rgb(0 0 0 / .18);           /* 外部投影 */
}

/* 高光叠加层 — 模拟光源在玻璃表面的反射 */
.liquid-glass-web-approx::before {
  content: "";
  position: absolute;
  inset: 0;
  z-index: -1;
  border-radius: inherit;
  background:
    radial-gradient(circle at 20% 0%, rgb(255 255 255 / .55), transparent 34%), /* 顶部径向高光 */
    linear-gradient(90deg, rgb(255 255 255 / .18), transparent 42%, rgb(255 255 255 / .14)); /* 水平高光条 */
  pointer-events: none;
}

/* 边缘细线 — 增加玻璃边缘的精细感 */
.liquid-glass-web-approx::after {
  content: "";
  position: absolute;
  inset: 1px;
  border-radius: inherit;
  border: 1px solid rgb(255 255 255 / .14);
  pointer-events: none;
}

/* 深色模式适配 */
@media (prefers-color-scheme: dark) {
  .liquid-glass-web-approx {
    border-color: rgb(255 255 255 / .18);
    background:
      linear-gradient(135deg, rgb(255 255 255 / .16), rgb(255 255 255 / .04)),
      rgb(15 23 42 / .42);                  /* 深色半透明基底 */
    box-shadow:
      inset 0 1px 0 rgb(255 255 255 / .22),
      0 18px 60px rgb(0 0 0 / .42);
  }
}

/* 用户偏好减少透明效果时的纯色回退 */
@media (prefers-reduced-transparency: reduce) {
  .liquid-glass-web-approx {
    background: rgb(255 255 255 / .96);     /* 不透明的近似替代 */
    backdrop-filter: none;
    -webkit-backdrop-filter: none;
  }
}
```

**重要：** `prefers-reduced-transparency` 的浏览器支持不均匀；测试它。即使没有模糊，也要始终提供足够的对比度。
